# Nimanto v0.5.0 — Clear Intent, Current Truth

Nimanto v0.5.0 concentrates decision-making at four high-leverage seams. A
candidate Application move is one policy-governed transaction; every role intake
route produces one consistently normalized current record; Workbench mutations
settle through one UI-only coordinator; and credential security remains separate
from navigation and accessibility behavior.

The result is less duplicated orchestration without widening Nimanto's authority.
Packet lifecycle effects are still system consequences, Action Intent remains a
server-side approval concept, and a current Role record is still not immutable
posting history or cross-source deduplication.

This remains a source-distributed local beta. There is no hosted candidate
backend, signed desktop binary, connected-account sender, employer screening,
legal advice, hiring prediction, or automatic application submission.

## What changed

### One candidate Application transition policy

The domain package now exposes one candidate transition interface: callers read
legal target options, see whether a target needs confirmation, and decide a
requested move. The board and table use that interface for controls and copy.
The Fastify route validates membership in the same closed status set and
forwards confirmation; transactional persistence makes the authoritative
policy decision under lock.

Consequential moves require `confirmed: true` at the HTTP boundary. Persistence
then locks the active tenant and current Application row, repeats the policy
decision, and writes status in the same transaction. The status update derives
`submittedAt` from the row PostgreSQL is actually changing, so entry stamping
and exit clearing cannot be based on a stale pre-read.

Packet generation and approval remain distinct actors. `PacketLifecycle`
explicitly requests the `prepared` or `approved_for_export` system consequence
and performs that write inside its existing packet/artifact/receipt transaction.
If the candidate has already recorded an external submission or withdrawal, the
policy preserves that fact and the lifecycle performs no Application write. The
pure policy does not absorb persistence atomicity or pretend these effects are
candidate board moves.

### Consistent current-Role normalization

Manual entry, allowlisted URL intake, Greenhouse, Lever, and Ashby now map their
source-specific observations through one domain normalizer. It applies common
NFC and trim rules, required-field checks, optional-field defaults, blank
requirement removal, and the existing `deep_link` capability while preserving
adapter-owned source identity, provenance, and content hash.

A complete provider batch is normalized before its write transaction starts, so
an invalid row rejects the bounded batch instead of producing a mixed shape.
Persistence continues to update or insert exactly one current row by
`(tenant, source, sourceJobId)`. This release deliberately adds no immutable Role
observation log, duplicate-link model, tombstone history, or cross-source dedupe.
Each Match Publication still freezes the exact normalized role input it used.

### A UI-only Workbench mutation coordinator

Workbench mutation callers now pass named operations—request, success copy, and
only the local commit, field recovery, or post-render focus they actually need.
The coordinator owns single-flight busy state, authentication and reachability
classification, one dashboard reconciliation, notice publication, and focus
ordering. Its request is an opaque closure, so the seam cannot become a universal
domain command bus or acquire Action Intent semantics.

The returned outcome distinguishes committed, failed, signed-out, unreachable,
and busy paths. Drafts, dialogs, and controls therefore clear or move focus only
after a successful commit. A successful sign-out or deletion can still retain
its completion notice even though the next dashboard refresh correctly reports
no active identity.

### Separate Identity and navigation/focus transitions

Identity transitions get first refusal on URL fragments. Invitation credentials
take precedence, bootstrap material is captured before history is scrubbed, and
unknown key/value fragments are scrubbed rather than treated as routes. Stable
errors never echo credential values. Identity loss owns credential and
identity-bound draft cleanup plus Deletion Run receipt retention.

A separate navigation/focus module owns only known section hashes, Back/Forward
restoration, mobile-dialog opening and focus trapping, desktop-width closure,
sticky-header scroll correction, and post-render focus. This keeps security,
privacy cleanup, routing, and accessibility behavior explicit without forcing
them into one generic browser framework.

### Dependency and verification maintenance

The current dependency graph incorporates the relevant open maintenance work on
the current release base: Fastify 5.11.3, Lucide React 1.31.0, Node type
definitions 26.2.0, tsx 4.23.12, and happy-dom 20.11.2. The macOS launcher now
enforces the same Node.js 24–26 range documented by the README. Reusing an
already-running Playwright server is an explicit local opt-in; CI continues to
start isolated services.

## Upgrade

Stop the API and copy the complete `.nimanto-data/` directory. Then use the
v0.5.0 source archive or exact tag and reinstall the locked dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

v0.5.0 introduces no schema migration. Startup remains on additive, idempotent
schema version 3, and existing candidate records, packet files, approvals, and
exact bindings are preserved. There is no schema downgrade path; restore the
stopped directory copy or fix forward instead of running older source against a
database after a later migration.

## Unchanged boundaries

- Imported claims remain pending until the candidate confirms them.
- Role rows remain current mutable records; immutable posting history and
  cross-source deduplication are not implemented.
- Sponsorship evidence remains historical, contextual, and never legal advice.
- Outcomes remain candidate-entered records; silence creates no employer state.
- Packet consequences do not prove external submission or replace candidate
  confirmation for a board move.
- Gmail, Outlook, form submission, hosted identity, desktop signing/notarization,
  backups, disaster recovery, and production legal review remain outside this
  release.
- The interface remains dark only; no light palette is claimed.
