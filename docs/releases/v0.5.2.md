# Nimanto v0.5.2 — Ask Clearly, Return Exactly

v0.5.2 is a source-distributed local-beta fix release. It closes three
interaction gaps at shared boundaries, refreshes the public explanation and
proof of the product, and folds current dependency maintenance into one verified
release tree. It adds no schema migration, provider, hosted service, model,
submission channel, or product authority.

## Improved

- **A confirmation has a keyboard way back.** Escape cancels every shared
  in-product confirmation without committing its action. Focus returns to the
  control that opened it, whether the candidate was rejecting a claim,
  discarding a draft, cancelling a schedule, or withdrawing an application.
- **The mobile drawer owns its complete focus order.** Forward and reverse Tab
  move through every visible drawer control in DOM order and wrap at the ends.
  The Brand-to-Close transition no longer depends on platform-specific native
  focus traversal.
- **Approved means the assurance gate is over.** After a packet is approved, its
  control no longer retains assurance-waiting copy or an obsolete
  `aria-describedby` relationship.
- **The public surface tells one current story.** README, website, metadata,
  screenshots, operations guidance, source-release paths, dependency
  inventories, and checksums describe the same `v0.5.2` source beta and its real
  boundaries.

## Maintenance

- Fastify 5.12.0, PGlite 0.5.5, and Next.js 16.3.1 are incorporated from their
  current maintenance branches.
- The release/SBOM toolchain uses CycloneDX cdxgen 12.8.3 and Concurrently
  10.0.5. Its exact Undici dependency is safely overridden to patched 7.29.0,
  and CI audits the full production and release-tool graph at high severity.
- CodeQL init and analyze are pinned together at 4.37.7 so the workflow cannot
  load one action version and execute the other.
- A version-synchronization gate now checks package manifests, API responses,
  provider user agents, container metadata, public links, current release notes,
  and SBOM destinations before the normal test suites run.
- A committed-asset preflight validates both release inventories and their exact
  checksum manifest. A disposable-data smoke run reproduces the reduced-motion
  synthetic screenshots, requires exact source and asset digests, requires the
  two public workbench copies to be byte-identical, and bounds cross-host pixel
  variance so operating-system rasterization cannot create a false stale result.
- The SBOM gate regenerates the current package-identity set and requires both
  committed inventories to match it exactly.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then use the
exact `v0.5.2` source tag or archive and reinstall the locked dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup remains on additive, idempotent schema version 3. No stored record
changes shape. Restore the stopped directory copy or fix forward rather than
running older source against a database after a future migration.

## Verification

The release gate covers:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm audit --prod --audit-level high
pnpm licenses:check
pnpm sbom:release
pnpm sbom:check
pnpm release:check
pnpm screenshots:check
graphify update .
```

The sequential WebKit journeys exercise the current public site and local
candidate workbench from 320 through 1440 CSS pixels, including keyboard focus,
confirmation cancellation, packet assurance/approval, reduced motion, and
200%-zoom-equivalent reflow. WebKit evidence is not a claim of physical touch,
screen-reader, Firefox, Chromium, or native Safari acceptance.

After downloading the three release assets into one empty directory, verify the
two inventories against the published manifest:

```bash
shasum -a 256 --check nimanto-v0.5.2-SHA256SUMS.txt
```

GitHub generates the source ZIP and tar archive from the tag. Nimanto does not
publish those archives as signed desktop artifacts.

## Still out of scope

Nimanto remains a candidate-side tool. It does not screen candidates for
employers, estimate hiring probability, provide legal advice, claim that an
employer currently sponsors transfers, infer outcomes from silence, send
through Gmail or Outlook, submit forms, host candidate data, or ship a signed
desktop installer. Local receipts are tamper-evident records, not proof of
external delivery.
