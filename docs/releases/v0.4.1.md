# Nimanto v0.4.1 — Action Before Analysis

Nimanto v0.4.1 is a focused user-flow and public-surface release. It protects a
long manual-role draft while the candidate moves through the workbench, puts the
application record before its analytics, gives board and table the same outcome
editor, keeps unchanged profile saves out of stored history, and reports packet
and export inventories literally.

It remains a source-distributed local beta. There is no hosted candidate backend,
signed desktop binary, connected-account sender, employer screening, legal
advice, hiring prediction, or automatic application submission.

## What changed

### 1. Manual role drafts survive section changes

**Role discovery → Add role** now uses a controlled draft held above workspace
section routing. Every field survives movement to another section and back. The
draft exists only in the current signed-in tab: reload, sign-out, identity
change, workspace deletion, successful save, or confirmed discard clears it.
Validation, network, and server failures preserve it.

### 2. Applications opens on the work

The board or table now follows the Applications introduction directly. The
funnel, record-review queue, and cohort counts remain available below it. Empty
and review-only states keep their next action beside that work surface rather
than presenting unrelated metrics first.

Board cards and table rows use the same labeled **Record outcome** editor. It
appends a candidate-reported outcome only; it never infers employer state or
changes application status. Inputs remain on failure, and focus returns to the
invoking control after save or cancel.

### 3. Section focus clears the sticky header

Workspace navigation now focuses and positions the destination using the actual
rendered header geometry. WebKit verification covers the responsive width matrix
and the 640 CSS-pixel equivalent of a 1280-pixel viewport at 200% zoom.

### 4. No-op profile saves no longer create history

Profile-version creation locks the active tenant, then compares NFC-trimmed
authorization wording and canonical confirmed-claim IDs inside the same
transaction. Unchanged input returns the existing version with an additive
`created: false` field; the existing top-level API response shape remains
compatible. The client disables its unchanged save control, but the server is
the correctness boundary.

### 5. Completion copy comes from returned data

Packet completion now reports the artifact manifest it actually received—for
the current generator, six files across four file types. Data Controls uses
literal singular/plural counts, including **1 application**.

## Public surface

The website keeps Nimanto's Colour & Material 002 system and invitation-fold
mark while putting the literal product job, source-distributed boundary, and
working run/source paths in the first viewport. A synthetic current-runtime
Applications screenshot shows the action-first surface. README, operations,
architecture, provider boundaries, metadata, manifest, notices, and SBOM links
are synchronized to v0.4.1.

## Upgrade

Use the v0.4.1 source archive or pull the tagged source, then install the locked
dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

There is no schema migration in v0.4.1. Stop the API before copying or backing up
`.nimanto-data/`. The previous known-good release is v0.4.0 at
`1fe95f291bd607685931299838b0a58f3409615f`; recovery is a redeploy of that exact
source or a newer fix-forward patch, never a rewritten tag or deleted candidate
data.

## Unchanged boundaries

- Imported claims remain pending until the candidate confirms them.
- Packets still assemble from confirmed evidence and locked authorization
  wording only.
- Application outcomes remain candidate-entered records; silence creates no
  employer outcome.
- Gmail, Outlook, form submission, desktop packaging/signing/notarization,
  hosted identity, backup guarantees, and production legal review remain
  outside this release.
- The interface remains dark only; no light palette is claimed.
