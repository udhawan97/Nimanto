# Nimanto v0.3.0 — Evidence Thread

Nimanto v0.3.0 makes the local workbench easier to narrow, explain, and audit
without weakening the candidate-controlled gates introduced in v0.1.0. It
remains a source-distributed local beta: there is no hosted candidate backend,
signed desktop application, connected-account sender, employer screening, legal
advice, or application submission.

## What changed

### 1. Private role narrowing

Role discovery can now search title, company, or location and combine source,
match-state, and tracking filters. Filter values remain in the open React view
only. They are not stored, exported, or sent to the API.

### 2. Recorded application timelines

Application cards and rows expose a chronological record of application creation
and candidate-reported replies, screens, interviews, offers, rejections, and
withdrawals. Nimanto does not reconstruct unrecorded stages or infer anything
from silence.

### 3. Sponsorship provenance and freshness

Each H-1B evidence signal now exposes its source type and locator, source period,
observation time, confidence, current/stale state, any original label changed by
the freshness rule, and the source's limitations. Historical evidence still
cannot establish current company policy, individual eligibility, or legal advice;
current role wording remains controlling.

### 4. Match anatomy

Expanded match details show `scoring_rules_v1`, coverage, the four documented
weighted dimensions, evidence-link counts, requirement states, exclusions, and
explicit blockers. Evidence Strength remains intentionally excluded from the
workbench view and is not presented as a score or hiring probability.

### 5. Tamper-evident local activity

A new deep-linkable **Local activity** section exposes verified internal match,
packet, and executed-action receipts with copyable input, artifact, and receipt
hashes. The store verifies each receipt hash on read. These records are unsigned
local history—not employer acknowledgments or proof of external delivery.

### 6. Packet review

Review packets now disclose canonical destination, summary, evidence-backed
claims, locked authorization wording, per-format document-inspection checks,
artifact hashes, and the latest stored assurance rule and findings before
approval. Inspection covers structure, integrity, and configured rules; it does
not verify claim truth, writing quality, employer acceptance, or delivery.

## Correctness

Assurance runs now receive a database-generated monotonic sequence. Both packet
review and packet approval resolve the latest run by this sequence, so two runs
created at the same database timestamp cannot be reordered by random UUID. The
schema addition is automatic and preserves existing local data.

## Public surface

The README, website, operating guide, provider boundary, architecture notes,
acknowledgments, notices, screenshots, social metadata, and machine-readable
dependency inventories are synchronized with v0.3.0. Historical v0.1.0 and
v0.2.0 release records and SBOMs remain in the repository for provenance.

## Upgrade

Pull or download the v0.3.0 source, then install the locked dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Existing local workspaces are upgraded in place when the API opens their PGlite
database. Back up `.nimanto-data/` while the API is stopped before moving a
workspace between releases. No schema downgrade is claimed.

## Verification

The release gate covers:

```bash
pnpm check
pnpm build
pnpm test:e2e
pnpm audit --prod --audit-level high
pnpm licenses:check
pnpm sbom:check
graphify update .
```

The end-to-end suite runs eight sequential Desktop Safari/WebKit journeys,
including public-site reflow and metadata, the six new review features, approval
gating, deletion recovery, section history, long-hash containment, and 320 px
layout checks.

Dependency inventories: [CycloneDX](nimanto-v0.3.0.cdx.json) and
[SPDX](nimanto-v0.3.0.spdx.json).

## Unchanged boundaries

- Imported claims remain pending until the candidate confirms them.
- Packets still assemble from confirmed evidence and locked authorization
  wording only.
- Packet assurance, packet approval, exact action approval, and the reset-on-
  restart runtime switch remain separate gates.
- Gmail, Outlook, form submission, desktop packaging/signing/notarization,
  hosted identity, backup guarantees, and production legal review remain outside
  this release.
- The interface remains dark only; no light palette is claimed.
