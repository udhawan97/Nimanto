# Nimanto v0.10.1 — Safer Role Intake and Local Files

v0.10.1 is a source-distributed security-maintenance release of the local beta.
It hardens role-text processing and local file boundaries, updates dependencies,
and makes the complete CodeQL candidate visible during review.

## Fixed

- HTML-backed job descriptions now use a streaming parser to extract text,
  decode entities once, and omit script, style, and template content. This is
  text extraction, not an HTML sanitizer. Provider-declared plain text stays
  literal.
- Location-preference parsing no longer repeatedly scans long whitespace. A
  redundant whitespace quantifier in résumé extraction was also removed.
- Local outbox writes validate the Action ID before filesystem effects.
  Packet artifact reads validate tenant, Packet, filename, and digest inputs
  before opening a file. These repairs close reproduced direct-helper path
  traversal cases; the HTTP routes already require owned records. No remote
  exploit was demonstrated, and this is not protection against an attacker
  who already controls the local filesystem.
- Reviewed URL intake rejects additional reserved and special-use addresses,
  checks both embedded Teredo addresses, and preserves the reviewed address
  family when connecting. Exact operator-reviewed hosts, public DNS checks,
  pinned connections, TLS verification, redirect denial, one deadline, and
  response-size limits remain in place.

## Maintenance

- Production and development dependencies, pnpm setup, and CodeQL actions are
  updated. Targeted transitive overrides remove vulnerable fast-uri, glob,
  and minimatch versions without changing the pnpm 11 runtime requirement.
- Pull-request CodeQL runs the complete candidate instead of limiting review
  to changed lines. Findings require individual source review; a successful
  scan is not a claim of zero findings.
- The website, README, screenshots, inventories, and installation guidance
  identify this exact source release. Published earlier inventories remain
  unchanged.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag.

These commands require Corepack to be installed. Node.js 25 and later
[do not bundle Corepack](https://nodejs.org/download/release/v25.8.0/docs/api/corepack.html);
follow the [Corepack installation guide](https://github.com/nodejs/corepack#installation)
first if `corepack --version` is unavailable. The repository pins pnpm 11.20.0.

[Playwright requires its matching browser binaries](https://playwright.dev/docs/browsers);
install WebKit before running browser or screenshot checks:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm exec playwright install webkit
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
pnpm recovery:drill
```

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.10.1/nimanto-v0.10.1.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.10.1/nimanto-v0.10.1.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.10.1/nimanto-v0.10.1-SHA256SUMS.txt)

```bash
shasum -a 256 --check nimanto-v0.10.1-SHA256SUMS.txt
```

The manifest covers exactly the two inventories. GitHub generates the tag ZIP
and tar archives; the manifest does not authenticate those archives. Nimanto
ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked dependencies, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.10.1
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

The supported Node.js range and schema version 15 are unchanged from v0.10.0.
Older databases still advance through the ordered migrations, and a runtime
refuses a database from a newer schema. Keep the stopped full-directory backup;
restore that copy or fix forward if rollback is needed. Schema downgrade
compatibility is not guaranteed.

## Boundaries

- This remains a candidate-controlled local beta. Matching is deterministic;
  it does not predict hiring outcomes or provide immigration or legal advice.
- Optional URL intake needs its operator-owned exact-host and terms-review
  configuration. External actions separately require the current Packet,
  assurance, exact Action approval, and a runtime switch that resets off.
- Recovery checks use disposable stopped copies. A backup from before deletion
  can restore deleted data; external suppression remains unimplemented.
- Connected-account sending, hosted backend operation, signed desktop
  packaging, notarization, automatic updates, and internet-exposure
  certification remain outside this release.
