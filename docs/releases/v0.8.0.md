# Nimanto v0.8.0 — Find It, Compare It, Keep It

v0.8.0 is a source-distributed local-beta decision-workspace release. It makes
retained evidence, roles, and applications easier to search and compare; keeps
candidate-owned role dispositions and private Application notes beside the work;
and adds bounded local exports for the exact view the candidate chose. Candidate
control, privacy, deterministic matching, and external-action authority do not
change.

## Added

- **Evidence search and filters.** Search literal claim, source-name, or locator
  text and combine evidence type, decision, and source filters. View state stays
  in the signed-in tab and never changes an evidence decision.
- **Two-Role comparison.** Select exactly two current Roles for a shared-line
  folio of literal role fields and each Role's latest stored Match Publication.
  Coverage, unmet requirements, blockers, compensation, and benefits remain
  visible without ranking either role or predicting an outcome.
- **Application search, filters, and sorting.** Search literal role, company,
  private-note, and candidate-reported outcome text; combine status, role-source,
  and follow-up filters; then sort by stored order, creation time, follow-up date,
  or role. These controls do not mutate records or funnel counts.
- **Candidate decision memory.** Archive or restore a Role without rewriting its
  source record. Retain a literal Application timeline of candidate-reported
  outcomes and private notes. Neither path invents an employer event or changes
  matching.
- **Focused local exports.** Export active candidate-set follow-up dates as an
  `.ics` file. Export the currently shown Applications as a formula-safe `.csv`
  containing literal tracker fields and note/outcome counts while excluding the
  private text bodies.

## Strengthened

- Overview, Evidence, Match, and Applications surfaces put the candidate's next
  task before secondary explanation. Consequential status moves, rejection,
  discard, and action controls retain explicit confirmation.
- Schema version 7 adds tenant-scoped Role dispositions and private Application
  notes without rewriting source Roles or candidate-reported outcomes. The
  ordered migration records completion only after its transaction commits.
- Evidence filtering, comparison, Application view derivation, calendar
  generation, and CSV generation are pure client-side seams. They add no API
  authority, provider, background job, browser storage, or hosted backend.

## Preserved

- Matching remains deterministic and evidence-linked; a comparison is not a
  recommendation or hiring probability.
- Follow-up dates remain candidate-set records. Nimanto creates no notification,
  employer contact, inferred response, or automatic status transition.
- Private note and outcome bodies remain outside the focused CSV. The sensitive
  JSON inspection export remains the complete candidate-owned archive.
- Packets still require assurance and approval. An external effect still
  requires the current packet, separate Action Intent approval, and the live
  runtime switch.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.8.0/nimanto-v0.8.0.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.8.0/nimanto-v0.8.0.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.8.0/nimanto-v0.8.0-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.8.0-SHA256SUMS.txt
```

The manifest covers exactly the CycloneDX and SPDX files. GitHub generates the
tag ZIP and tar archives; the manifest does not authenticate those archives,
and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.8.0
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup advances the database through ordered migrations to schema version 7.
Version 7 adds tenant-scoped Role dispositions and private Application notes.
It does not rewrite source Roles, candidate-reported outcomes, packets, or
external actions. Keep the stopped full-directory backup: the beta does not
guarantee schema downgrade compatibility, so restore the copy or fix forward
rather than opening a version-7 database with older source.

## Boundaries

- This remains a candidate-controlled local beta, not employer screening, legal
  advice, or a hiring probability estimate.
- Search and comparison operate on literal retained records; they do not infer
  why an employer acted or reconstruct missing stages.
- Focused exports are explicit local downloads. They create no Nimanto reminder,
  background contact, restore protocol, or connected-account effect.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
