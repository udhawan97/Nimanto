# Nimanto v0.10.0 — Keep the Record, Prove the Handoff

v0.10.0 is a source-distributed local-beta workflow release. It turns a
confirmed career record into current Match explanations, candidate-selected
Packets, inspectable Application Dossiers, append-only Submission Records, and
one candidate-owned Career Ledger. Candidate control, deterministic matching,
privacy, and external-action authority remain unchanged.

## Added

- **Candidate-selected packet composition.** A Packet binds one ordered set of
  confirmed Evidence Claims to the Application's exact Profile Version, current
  Match Publication, role content hash, and deterministic `packet_v2` canonical
  content. Identical frozen inputs reproduce the same canonical hash.
- **Append-only Submission Records.** The candidate records an external
  submission only after performing it, with the channel, destination, time, and
  either the exact approved Packet formats used or an explicit materials gap.
  Nimanto does not call this an employer receipt or delivery confirmation.
- **Application Dossiers and Career Ledger.** Each Application can open a
  read-only dossier over its current role, Match, Packet and assurance history,
  candidate-authored activities, interview rounds, people, answer revisions,
  saved review views, descriptive timing observations, offer terms, actions,
  and Submission Records.
- **Inspectable Match Evidence Lens.** New Match Publications store the exact
  supported, source-linked, and candidate-attested-only requirement counts
  behind the separate Evidence Strength ordinal. The unweighted source mix
  cannot change the fit band and is never a hiring or immigration probability.
- **Synthetic stopped-copy recovery drill.** `pnpm recovery:drill` checks a
  stopped synthetic database copy, all six Packet artifacts, tenant isolation,
  approval reset, interrupted actions, and deletion recovery without touching
  candidate data.

## Strengthened

- Packet, Match, Profile, role, evidence, artifact-manifest, and submission
  currentness are rechecked under tenant-scoped transaction locks before
  consequential transitions.
- Manual launch-key entry remains editable after a rejected key, with launcher
  fragments and invitation precedence preserved. Fragment keys continue to use
  bounded sessionStorage; manual corrections are not persisted before acceptance.
- Optional reviewed URL intake now rejects incomplete response streams and owns
  one ten-second deadline across DNS, headers, and body while preserving exact
  hosts, pinned public DNS, redirect denial, and bounded content.
- Ambiguous external actions expose their exact Action ID and provider-specific
  do-not-retry reconciliation path without adding a retry or claiming delivery.
- Packet history now explains timestamp-free `packet_v2` canonical hashes and
  separate artifact-manifest hashes accurately.
- Schema version 15 adds idempotent manual-role operation records, answer-block
  prompt/topic provenance, legacy manual-role identity review, and corrected
  migration-marker observation times.

## Preserved

- Matching remains deterministic and candidate-side. Nimanto does not screen
  candidates for employers, rank people, predict hiring outcomes, or provide
  legal, tax, immigration, negotiation, or financial advice.
- Historical government evidence never proves that a current employer or Role
  sponsors an H-1B transfer.
- A Packet still requires assurance and approval. An external effect still
  requires the current Packet, separate Action Intent approval, and a live
  runtime switch that resets off.
- Ambiguous work remains a do-not-retry audit trail. Connected accounts,
  employer form submission, silent sends, and automatic retries remain outside
  this release.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.10.0/nimanto-v0.10.0.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.10.0/nimanto-v0.10.0.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.10.0/nimanto-v0.10.0-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.10.0-SHA256SUMS.txt
```

The manifest covers exactly the CycloneDX and SPDX files. GitHub generates the
tag ZIP and tar archives; the manifest does not authenticate those archives,
and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.10.0
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup advances an older database through the ordered migrations to schema
version 15 and refuses a database created by a newer runtime. Keep the stopped
full-directory backup: the beta does not guarantee schema downgrade
compatibility, so restore the copy or fix forward.

## Boundaries

- This remains a candidate-controlled local beta, not employer screening, legal
  advice, an immigration conclusion, or a hiring probability estimate.
- Recovery evidence covers stopped synthetic copies. Restoring a backup taken
  before deletion can resurrect deleted data; external suppression is not
  implemented.
- Optional reviewed URL intake remains disabled unless its exact-host and
  terms-review configuration is present.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, automatic updates, and internet-exposure certification remain
  outside this release.
