# Nimanto v0.4.2 — Exact Review, Exact Commit

Nimanto v0.4.2 tightens the candidate-controlled workflow at the points where a
reviewed value becomes a stored or executable one. Evidence import is atomic,
matches are published from exact frozen inputs, packet assurance and action
approval bind the exact artifacts they reviewed, discovery and government data
ingestion commit coherently, and deletion fences every later workspace write.

The release also completes five user-flow passes: notices stay in view, invalid
compensation fields receive precise guidance and focus, mobile navigation is a
real modal with a focus trap, the public header reflows at 320 px, and the full
workbench remains keyboard- and WebKit-tested.

It remains a source-distributed local beta. There is no hosted candidate
backend, signed desktop binary, connected-account sender, employer screening,
legal advice, hiring prediction, or automatic application submission.

## What changed

### Exact-snapshot match publication

Manual and scheduled scoring now use one `MatchPublication` module. It loads the
exact Profile Version, evaluates only its frozen confirmed claim IDs, hashes the
normalized job snapshot, job content hash, profile input hash, claim IDs, and
rule version, then stores the match run and receipt in one transaction. The
receipt includes evidence used by both requirements and match dimensions.

### Candidate-approved evidence intake

Preview and import now share one bounded 500-claim projection and canonical
hash. Preview writes nothing. Changed content, an invalid confirmation hash, an
Nth-row failure, or a workspace deletion rolls the entire pending claim batch
back. Raw uploads remain transient, prohibited document material still fails
closed, and LinkedIn archive exclusions remain explicit.

### Staged packet and exact assurance lifecycle

Packet artifacts render and undergo deterministic inspection in a private
staging directory. Before promotion, the transaction revalidates the exact
application, profile, job, and evidence snapshot. Assurance stores the exact
packet-content and manifest hashes. Approval compare-and-swaps the latest
passing assurance against those hashes, so changed artifacts or a newer review
cannot inherit an older approval.

### Exact-approved external actions

Action approval binds an immutable intent hash—packet, provider, target, and
payload—to the exact approved packet hash. Execution revalidates both and still
requires the separate in-memory switch, which starts off after every restart.
If a provider effect may have succeeded but local persistence is uncertain, the
action becomes `ambiguous`; interrupted executions are recovered as ambiguous
on restart, and neither case retries automatically. The only implemented
providers remain a user-opened mail deep link and the private local test outbox.

### Durable discovery and dataset editions

Direct provider import and scheduled refresh are now distinct `DiscoveryCycle`
operations. Direct import fetches before its database transaction and commits
the role batch without scoring. Scheduled refresh first claims a durable lease,
then fetches, then atomically commits its role/match/receipt batch and cadence
advance through the same exact match publication path as manual scoring.

Government imports validate every row before writes and store an edition with
source family, source edition, checksum, transformation version, evaluation,
and trusted evaluation provenance. Replaying the same edition is idempotent;
changing its checksum or transformation is a conflict. Historical government
rows cannot become current-role/current-policy guarantees or absence-derived
negative policy claims.

### Resumable deletion write fence

Beginning deletion locks the active tenant row, flips it to deleting, and
captures the outbox cleanup inventory in the same transaction. A database
trigger serializes every later tenant-owned insert or update against that lock.
An authenticated write or provider effect therefore finishes before deletion or
fails; it cannot escape cleanup. Database deletion, pending file cleanup, resumption,
and final completion remain separately truthful states behind the hashed
seven-day status token.

### One application transition policy

The workbench now consumes the domain package's legal transition and
confirmation policy instead of maintaining a second client-side table.
Server-side enforcement remains authoritative.

### Flow and responsive polish

- Sticky success/error notices remain visible and generic failures receive
  focus for assistive-technology and keyboard recovery.
- Compensation validation identifies the exact field and returns focus there.
- Mobile navigation uses dialog semantics, focus trapping, background inertness,
  escape/backdrop close, and breakpoint cleanup.
- Public navigation wraps cleanly at 320 px.
- Existing action-first Applications, retained history, packet review, sensitive
  export, and deletion receipt flows remain intact.

## Upgrade

Stop the API and copy the complete `.nimanto-data/` directory. Then use the
v0.4.2 source archive or exact tag and reinstall the locked dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup applies additive, idempotent schema version 3. It preserves v0.4.1
candidate data and adds packet/assurance bindings, action bindings, dataset
editions, and the active-tenant write fence. Existing approved packets remain
approved. An approved action without the new exact binding returns to pending
approval, and an unapproved packet needs a fresh assurance run before approval.
There is no downgrade migration;
restore the stopped directory copy or fix forward instead of running older
source against the migrated data.

## Unchanged boundaries

- Imported claims remain pending until the candidate confirms them.
- Sponsorship evidence remains historical, contextual, and never legal advice.
- Outcomes remain candidate-entered records; silence creates no employer state.
- Gmail, Outlook, form submission, hosted identity, desktop signing/notarization,
  backups, disaster recovery, and production legal review remain outside this
  release.
- The interface remains dark only; no light palette is claimed.
