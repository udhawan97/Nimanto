# Nimanto v0.9.0 — Choose the Search, Keep the Evidence

v0.9.0 is a source-distributed local-beta discovery release. It lets the
candidate approve one explicit search contract, inspect why every retained Role
is recommended or excluded, and keep source, freshness, provenance, and H-1B
context separate. Candidate control, deterministic matching, privacy, and
external-action authority do not change.

## Added

- **Candidate-approved Discovery Profiles.** Choose role families, titles,
  literal seniority, industry, and skill terms, physical and remote-eligible
  areas, commute and relocation preferences, work modes, posted-compensation
  floor, observation age, authorization-review date, and enabled sources. The
  profile links to one exact Evidence Profile; résumé evidence never silently
  becomes a search preference.
- **Inspectable recommendations.** Every searchable Role exposes the exact
  matched, excluded, and unresolved Discovery Profile reasons. Missing
  compensation, coordinates, or authorization review stays unresolved instead
  of becoming an inferred match. Outside-recommendation Roles remain
  searchable.
- **Source-preserving market evidence.** Source runs, normalized Role
  Observations, current availability, and verification attempts remain separate.
  Exact-field clusters can show possible variants without merging their source
  identity, wording, links, or lifecycle.
- **Inspectable provenance and employer routes.** Role cards distinguish
  source-posted, source-updated, observed, verified, and local-update times. An
  approved Greenhouse, Lever, or Ashby target can open through a fixed,
  tracking-free ATS route. A separate candidate-requested recheck records
  present, not-found, absent-from-complete-list, or blocked evidence without
  applying or following redirects.
- **Qualified H-1B context.** Current posting wording, current
  employer-authored policy, and historical government evidence appear as
  separate facts. Exact wording acknowledgement is bound to one Role snapshot.
  Candidate-reviewed employer aliases and government dataset editions are
  accepted only through checksum-bound provenance and language-review gates;
  no production government edition or qualified review ships by default.

## Strengthened

- Role discovery now has one pure projection over a frozen dashboard snapshot
  and injected evaluation time. It owns joins, profile replay, recommendation
  membership, filters, assessment-preserving grouping, representative ordering,
  comparison selection, suggestions, and coherent counts. The workbench receives
  render-ready groups and retains rendering, focus, browser state, and candidate
  actions.
- Publication freshness fails closed. One miss from a complete source listing
  means `possibly_closed`; only a second complete miss at least six hours later
  can mean `closed`. Failed and partial runs cannot close a Role.
- The source registry remains the execution boundary. Greenhouse, Lever, and
  Ashby are enabled; SmartRecruiters and broader licensed or partner candidates
  remain non-executable until their exact source rights are approved.

## Preserved

- Matching still uses confirmed evidence frozen by one exact profile version and
  Role content hash. Discovery is not a hiring probability or employer ranking.
- Historical government records never prove that a current employer or Role
  sponsors an H-1B transfer. Nimanto gives no legal advice.
- Discovery and verification do not apply, submit, contact an employer, or create
  a connected-account effect.
- Packets still require assurance and approval. An external effect still
  requires the current packet, separate Action Intent approval, and the live
  runtime switch.
- Schema version remains 7. This release adds no schema migration, hosted
  backend, browser storage, provider credential, notification service, or
  automatic retry.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.9.0/nimanto-v0.9.0.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.9.0/nimanto-v0.9.0.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.9.0/nimanto-v0.9.0-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.9.0-SHA256SUMS.txt
```

The manifest covers exactly the CycloneDX and SPDX files. GitHub generates the
tag ZIP and tar archives; the manifest does not authenticate those archives,
and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.9.0
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

The database remains at schema version 7. Startup still runs the ordered,
recorded migration preflight and refuses a database created by a newer runtime.
Keep the stopped full-directory backup: the beta does not guarantee schema
downgrade compatibility, so restore the copy or fix forward.

## Boundaries

- This remains a candidate-controlled local beta, not employer screening, legal
  advice, or a hiring probability estimate.
- Discovery operates on candidate-approved inputs and retained source facts. It
  does not infer current sponsorship, why an employer acted, or missing
  compensation and geography.
- Candidate-requested ATS rechecks are read-only publication evidence. They
  never submit an application or authorize redirect following.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
