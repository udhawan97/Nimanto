# Nimanto v0.6.0 — Follow Up on Your Terms

v0.6.0 is a source-distributed local-beta feature release. A candidate can now
store one explicit follow-up date on an active application, see that same date
on the board and table, and use it as the controlling date in Review due. This
is a candidate record, not a notification or employer signal: Nimanto does not
contact anyone, run a reminder service, infer a response, or change application
status from the date.

## Added

- **Candidate-set follow-up dates.** Set, change, clear, or explicitly discard a
  date draft from either application view. Unsaved values remain only in the
  signed-in tab across section changes and clear at identity boundaries.
- **Literal due-state visibility.** Board and table show the same saved date and
  whether it is due. Review due distinguishes candidate-set dates from the
  existing activity-based fallback.
- **Strict tenant-scoped storage.** Additive schema version 5 adds nullable
  `applications.follow_up_on`. The API accepts one real `YYYY-MM-DD` value or
  `null` and rejects ambiguous strings, impossible dates, timestamps, and empty
  strings.

## Refined

- A future candidate-set date suppresses the 336-hour activity fallback until
  that local calendar day. Clearing it returns the application to fallback
  behavior.
- Saving restores focus to the originating control. Clearing does the same
  while that control remains available; if clearing an inactive withdrawn date
  removes the control, focus returns to the application record. The date editor
  stays contained at 320, 375, and 1280 pixels, and both application views
  expose the saved state.
- The record-review queue names whether each item came from a stored date or a
  derived activity deadline. Withdrawn applications remain excluded; any saved
  date stays visible but inactive, can be cleared, and becomes active again if
  the application returns to Tracked. A new or changed date cannot be saved
  while withdrawn.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

The browser gate runs twenty sequential WebKit journeys across the public site,
private workspace, session boundaries, draft preservation, candidate-set
follow-up dates, packet currentness, accessibility recovery, and narrow-screen
layout.

Download these three release assets into one empty directory:

The checksum manifest covers exactly the CycloneDX and SPDX files. GitHub
generates the tag ZIP and tar archives; the manifest does not authenticate those
archives, and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.6.0
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup applies additive, idempotent schema version 5. Existing applications
receive no follow-up date and continue to use the derived 336-hour review
fallback. Keep the stopped full-directory backup: the beta does not guarantee
schema downgrade compatibility, so restore the copy or fix forward rather than
opening a version-5 database with older source.

## Boundaries

- A saved follow-up date is not a local, push, email, or background
  notification. The candidate must open Nimanto to see it.
- The date does not imply an employer reply, rejection, interview, or any other
  outcome, and it never changes application status.
- Withdrawing an application retains an existing date as an inactive candidate
  record. It does not remain in Review due, and no new or changed date can be
  saved until the application returns to Tracked; clearing remains available.
- This remains a candidate-controlled local beta, not employer screening or a
  hiring probability estimate.
- Matching remains deterministic and evidence-linked; imported claims remain
  pending until the candidate confirms them.
- Packets require assurance and approval. External effects require the current
  packet, separate action approval, and the live runtime switch.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
