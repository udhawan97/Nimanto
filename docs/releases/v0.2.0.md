# Nimanto v0.2.0 — Colour & Material

Still a local beta. Every gate from v0.1.0 stands: imported claims stay pending
until you confirm them, packets assemble from confirmed evidence only, and
nothing leaves the machine without assurance, a packet approval, an action
approval, and a runtime switch that resets itself off.

What changed is how it looks, and what it does with what it already knew.

## The mark

Nimanto now has its own emblem: a **fold lotus** — five brass-edged petals
opening about a single axis, two ivory outer and three lacquer inner, with an
emerald seed at the centre and a vermilion light behind it.

It ships three ways, all from one geometry:

- **Live WebGL** on the landing page, with a studio environment map, real
  shadows and a click ceremony. `three` is bundled, never fetched — the brand
  source loaded it from a CDN, which would have broken the no-external-request
  posture and offline use. It is dynamically imported, so the workbench route
  never downloads it.
- **An animated SVG** in the README. SMIL rather than CSS, because GitHub
  renders README images through a proxy where CSS animation is unreliable;
  finite at 4.4s, because WCAG 2.2.2 wants a pause control past five seconds and
  a README has none.
- **A flat SVG** for the app icon, favicon, PWA, social card and workbench
  chrome, projected from the same petal geometry so they read as one object.

## Colour & Material 002

The whole interface moves to a dark system sampled from the emblem: ink,
lacquer, ivory stone, aged brass, the emerald seed, one vermilion light. The
governing proportion is **ink 74 · stone 16 · brass 7 · vermilion 2 ·
emerald 1** — brass is a line weight and never a fill; vermilion earns its place
once per screen.

Two things worth stating plainly:

- **Every contrast figure is computed, not quoted.** The palette sheet this was
  sampled from labelled brass and vermilion AAA at 6.97:1 and 6.90:1; both are
  AA. Chip text and borders are measured against their own fill rather than the
  page, which moved three border tokens up a ramp step. A test in `apps/web`
  now asserts all of it, including the WCAG 1.4.11 non-text floor.
- **The interface is dark only.** The palette defines no light ground and every
  ratio in it is computed against ink, so a light theme would be a second,
  unsampled palette. There was no light/dark choice before either, so nothing is
  taken away — but readers who need light-on-dark disabled have no opt-out, and
  that is a real cost rather than an oversight.

Type moves to Archivo, IBM Plex Mono and Instrument Serif, all self-hosted.

## The website

Rebuilt as six movements on ink: the emblem as the page, then thesis, method,
a worked example, the product boundary, and how to run it. Method is four plates
on one jaali-pierced brass spine rather than four cards. The boundary band is
the only large light field in the system, which is what the palette reserves
ivory stone for.

## The workbench

Same palette, calmer. Beyond the restyle, six changes that came out of a
[flow analysis](../superpowers/specs/2026-08-05-user-flow-analysis.md) of where
the tool used to dead-end:

- **Pipeline board** over the real application status union, alongside the
  existing table. Moves are buttons rather than drag, so it is keyboard-operable
  by construction.
- **Next-step rail** on Overview, ordered by where the flow is blocked earliest.
  A new workspace previously showed four zeros and no instruction.
- **Command palette** (⌘K) reaching sections, roles and applications. Entries
  carry a destination and cannot hold a callback, so nothing approval-gated is
  reachable from it.
- **Funnel on Overview** — counts and the API's own caveat, never a conversion
  rate. A percentage off a sample of two would be the hiring-probability claim
  this product refuses to make.
- **Follow-up observation** that reads "nothing recorded since ⟨date⟩". Never
  "stale" or "cold": Nimanto does not infer an outcome from silence.
- **Error boundary and honest connection state.** The old "Local service
  connected" indicator was static markup — it said connected whether or not
  anything was. The workbench now distinguishes a browser that is offline from
  an API that is not running, and says which.

## Correctness

- **Application transitions are now guarded.** `PUT /v1/applications/:id/status`
  validated union membership only, and the store stamped `submitted_at` on entry
  to `submitted_externally` and never cleared it. One mis-set status therefore
  wrote a permanent, false record that the candidate had submitted something. A
  transition whitelist in `packages/domain` is enforced in the API route, the
  three consequential columns confirm first, and leaving `submitted_externally`
  now clears the timestamp. Packet creation and packet approval keep writing
  their statuses as system consequences.
- **First tests in `apps/web`** — the package ran `--passWithNoTests` with zero.

## Verification

`pnpm check`, `pnpm build` and `pnpm test:e2e` pass. `pnpm audit --prod` reports
no known vulnerabilities. SBOMs are regenerated as
[CycloneDX](nimanto-v0.2.0.cdx.json) and [SPDX](nimanto-v0.2.0.spdx.json); the
v0.1.0 pair is retained for provenance.

Two limits worth naming:

- CI runs WebKit, which has no hardware WebGL, so the e2e exercises the emblem's
  **fallback ladder** rather than the live hero. The WebGL hero is verified
  manually.
- The proportion rule above is a design heuristic, not an automated gate. No
  pixel-histogram tool exists in this repo and adding one was not in scope.

## Unchanged

The product contract, the trust model, every approval gate, the domain rules,
the parsers, the provider allowlists and the packet formats. Generated DOCX and
PDF packets stay unbranded — ATS-safe output should not carry brand colour. The
README architecture diagram keeps GitHub's default colours.

Desktop packaging, hosted identity, connected-account sending and production
legal review remain release gates, exactly as in v0.1.0.
