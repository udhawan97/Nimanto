## Deviations recorded after v0.2.0

- **Match artifact hashes do not reproduce across `95b369f`.** `artifactHash` is computed over the whole match result, and `evidenceStrength` is a field of it. That ordinal was corrected — it previously divided a set by itself, so it could only ever return `source_strong` and `source_mixed` was unreachable. A match run recorded before that commit therefore re-runs to a different `artifactHash` on the same frozen input. `ruleVersion` is deliberately **not** bumped: `scoring_rules_v1` names the band cut-points, which are unchanged, and the product contract defines Evidence Strength as a separate ordinal. Every pre-change value was provably wrong, so no correct receipt was invalidated.
- **Evidence Strength uses an unweighted `supported` denominator.** The product contract specifies the share of _known weighted_ requirements. The implementation divides by the count of supported requirements and applies no weights. Pre-existing; unchanged by the correction above; recorded here rather than silently carried.
- **Synthetic starter and demo workspaces report `source_limited`.** Their seeded claims are marked user-attested, so they are not counted as source-linked. This is the corrected reading, not a regression. New Match Publications now persist `evidence_strength_unweighted_v1` plus the exact supported/source-linked/candidate-attested-only counts, and the workbench renders that basis in Role discovery and Application Dossiers. Historical runs retain their literal ordinal without reconstructed counts. The weighted-requirement deviation above remains open and visible.
