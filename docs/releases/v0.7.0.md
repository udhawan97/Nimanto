# Nimanto v0.7.0 — One Place for Each Promise

v0.7.0 is a source-distributed local-beta architecture release. It gives the
Applications workbench one explicit state model, assembles Dashboard data inside
one coherent read boundary, centralizes candidate follow-up rules in one pure
policy, and replaces open-time schema patching with ordered, recorded
migrations. Candidate control, privacy, and external-action authority do not
change.

## Deepened

- **One Applications working-state module.** Board/table choice, Review filters,
  cohort inputs, candidate-reported outcome drafts, and follow-up drafts share
  one identity-bounded reducer. Switching sections preserves work; reload,
  sign-out, deletion, and identity replacement clear it. A delayed mutation
  clears only the exact snapshot it submitted.
- **One coherent Dashboard read.** The API composes Dashboard lists,
  enrichments, and candidate-outcome counts inside one database transaction.
  Exact latest-record selection remains in persistence. Application records
  retain literal candidate-reported outcome histories, while the
  `personalFunnel` aggregate is counts-only rather than inferred employer
  meaning.
- **One follow-up policy.** The domain owns strict real `YYYY-MM-DD` parsing,
  legal changes, inactive withdrawn behavior, and candidate-local due-day
  evaluation. The API, database, and workbench use that same rule.
- **One ordered migration path.** Fresh databases begin at the current schema;
  existing databases advance through committed steps. Schema version 6
  transactionally backfills canonical Packet manifest and Action Intent hashes,
  records completion only after commit, resumes safely after interruption, and
  rejects databases created by a newer runtime. Startup still transactionally
  replays idempotent base and tenant-trigger definitions so incomplete
  local-beta fixtures can recover; only missing versions run one-time schema or
  data mutations.

## Preserved

- A follow-up date is a candidate record, not a notification, employer contact,
  inferred response, application transition, or background job.
- Working state remains private to the signed-in tab and is never written to
  browser storage.
- Application records retain literal candidate-reported outcome histories; the
  Dashboard `personalFunnel` exposes only aggregate counts.
- Matching remains deterministic and evidence-linked. Packets still require
  assurance and approval; an external effect still requires the current packet,
  separate Action Intent approval, and the live runtime switch.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

The automated gate runs 284 unit, integration, contract, and release-asset tests
plus twenty sequential WebKit journeys across the public site, private
workspace, identity boundaries, tab-local draft preservation, application
follow-up behavior, packet currentness, accessibility recovery, and
narrow-screen layout.

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.7.0/nimanto-v0.7.0.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.7.0/nimanto-v0.7.0.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.7.0/nimanto-v0.7.0-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.7.0-SHA256SUMS.txt
```

The manifest covers exactly the CycloneDX and SPDX files. GitHub generates the
tag ZIP and tar archives; the manifest does not authenticate those archives,
and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git fetch --tags origin
git checkout v0.7.0
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup advances the database through ordered migrations to schema version 6.
Version 6 adds no candidate-facing column; it transactionally backfills
canonical hashes for legacy Packet manifests and Action Intents. A migration
version is recorded only after its work commits, and a database created by a
newer runtime fails closed. Keep the stopped full-directory backup: the beta
does not guarantee schema downgrade compatibility, so restore the copy or fix
forward rather than opening a version-6 database with older source.

## Boundaries

- This remains a candidate-controlled local beta, not employer screening, legal
  advice, or a hiring probability estimate.
- The architecture changes do not add notifications, provider access,
  connected-account sending, application submission, or employer-side
  authority.
- A saved follow-up date does not imply an employer reply, rejection,
  interview, or other outcome, and it never changes application status.
- Candidate outcomes are recorded literally; aggregate counts do not establish
  why an outcome occurred.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
