# Nimanto v0.5.4 — Work Stays Yours

v0.5.4 is a source-distributed local-beta workflow and identity-safety release.
It keeps unfinished candidate work stable while moving around the workbench,
binds browser writes to the exact loaded session, and prevents a historical
packet from producing a new handoff. It adds one additive local schema migration
for exact packet-generation order, but no hosted service, provider, model,
submission channel, or product authority.

## Improved

- Evidence fields, role search and filters, manual role details, action fields,
  outcome notes, application views, record-review filters, and cohort inputs now
  stay with the current signed-in tab across workbench section changes.
- Import preview, draft discard, and successful commits return focus to the
  relevant control without making a later response erase newer typing.
- Long candidate and source values wrap at narrow widths, and primary workbench
  navigation controls meet the 44-pixel touch-target floor.
- Lucide React moves to 1.32.0. Release tooling moves to CycloneDX cdxgen 12.8.4
  and Vitest 4.1.11; the lockfile and release inventories describe one verified
  dependency tree.

## Fixed

- Evidence, role, action, and outcome saves clear only the exact snapshot they
  submitted. Edits entered while a request is in flight stay in the form.
- Each application keeps its own unfinished outcome draft. Opening another
  application's editor no longer replaces the note already in progress.
- Every authenticated browser mutation carries the session generation that
  loaded its workspace. The API rejects a missing or stale generation with
  `IDENTITY_CHANGED` before the route handler can write, and the client clears
  identity-bound content before loading a replacement workspace.
- Child-local import state remounts at the new identity epoch, preventing a file
  preview from crossing a sign-out, revocation, invitation, or deletion boundary.
- Action creation, approval, and execution now share the packet-generation
  tenant lock and require the application's latest packet to be approved.
  Execution rechecks immediately before the provider effect, so an older
  approved packet cannot be reused after a newer generation exists.
- Schema version 4 assigns every packet a monotonic internal generation
  sequence under that lock. Current-packet selection and packet history use the
  sequence instead of timestamp and random-ID tie-breaking.
- Conditional relationships such as `aria-controls` are exposed only while the
  controlled surface exists.
- `pnpm screenshots:render` now builds the complete current source tree before
  it captures and updates governed assets, preventing an old static export from
  being relabeled with a new source-evidence digest.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm licenses:check
pnpm sbom:check
pnpm release:check
```

The browser gate runs nineteen sequential WebKit journeys, including overlapping
draft saves, identity replacement, direct stale-session API writes, current-
packet action creation, explicit discard/focus recovery, and 320-pixel wrapping.
The screenshot update command performs its own production build before capture.

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.5.4/nimanto-v0.5.4.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.5.4/nimanto-v0.5.4.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.5.4/nimanto-v0.5.4-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.5.4-SHA256SUMS.txt
```

The checksum manifest covers exactly the CycloneDX and SPDX files. GitHub
generates the tag ZIP and tar archives; the manifest does not authenticate those
archives, and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git checkout v0.5.4
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Startup applies additive, idempotent schema version 4. It adds an internal packet
generation sequence and preserves every existing packet and artifact. Existing
rows are backfilled in their previous deterministic `created_at`/ID order; a
pre-v0.5.4 timestamp tie did not persist the true insertion order, so startup
cannot reconstruct more history than the old schema recorded. Packets created
after the upgrade have exact monotonic generation order under the tenant lock.
A stopped full-directory backup remains required, and downgrade compatibility is
not guaranteed.

## Boundaries

- This is a candidate-controlled local beta, not employer screening or a hiring
  probability estimate.
- In-tab working state is not durable storage: reload, sign-out, deletion, and
  identity changes deliberately clear it.
- Matching remains deterministic and evidence-linked; imported claims remain
  pending until the candidate confirms them.
- Packets require assurance and approval. External effects require the current
  packet, separate action approval, and the live runtime switch.
- Local receipts are not proof that an employer received anything.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
