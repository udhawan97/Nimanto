# Nimanto v0.5.3 — Proof Means Enforced

v0.5.3 is a source-distributed local-beta verification hotfix. It preserves the
candidate-facing interaction, documentation, and dependency improvements from
v0.5.2 while closing the final screenshot-evidence gap found during the second
council review's targeted closure. It adds no schema migration, provider,
hosted service, model, submission channel, or product authority.

## Fixed

- The screenshot gate now explicitly requires the committed documentation and
  public workbench PNGs to be byte-identical. Their independently recorded
  digests were already equal, but a future divergent pair plus an updated
  manifest could previously pass.
- A negative script test proves that divergent documentation/public bytes fail
  closed. The existing source digest, asset digests, disposable synthetic
  capture, exact dimensions, and bounded cross-host visual comparison remain in
  force.
- The public website, README, runtime identities, operations guidance, version
  seams, release inventories, and checksums now point to the immutable v0.5.3
  source release. v0.5.2 remains an unchanged historical release.

## Included from v0.5.2

- Escape cancels shared in-product confirmations without committing and returns
  focus to the control that opened them.
- The complete mobile drawer follows one deterministic forward/reverse focus
  order and wraps at both ends.
- Approved packets stop retaining obsolete assurance-waiting descriptions.
- The public Run, Release, and Help paths describe exactly three bounded runtime
  choices and distinguish GitHub tag archives from Nimanto's two SBOM assets and
  checksum manifest.
- The dependency, CodeQL, full high-severity audit, SBOM-freshness, screenshot,
  and same-SHA Pages gates remain part of CI.

## Verify

Use Node.js 24–26 and pnpm 11 from a clean checkout of the exact tag:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
pnpm screenshots:check
pnpm audit --audit-level high
pnpm sbom:check
pnpm release:check
```

Download these three release assets into one empty directory:

- [CycloneDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.5.3/nimanto-v0.5.3.cdx.json)
- [SPDX inventory](https://github.com/udhawan97/Nimanto/releases/download/v0.5.3/nimanto-v0.5.3.spdx.json)
- [SHA-256 manifest](https://github.com/udhawan97/Nimanto/releases/download/v0.5.3/nimanto-v0.5.3-SHA256SUMS.txt)

Then run:

```bash
shasum -a 256 --check nimanto-v0.5.3-SHA256SUMS.txt
```

The checksum manifest covers exactly the CycloneDX and SPDX files. GitHub
generates the tag ZIP and tar archives; the manifest does not authenticate those
archives, and Nimanto ships no signed installer or desktop binary.

## Upgrade

Stop Nimanto and copy the complete `.nimanto-data/` directory. Then check out
the exact tag, reinstall the locked graph, and start the local beta:

```bash
git checkout v0.5.3
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

v0.5.3 adds no Nimanto schema migration. It preserves the v0.5.2 application
data shape, but a backup remains required and downgrade compatibility is not
guaranteed.

## Boundaries

- This is a candidate-controlled local beta, not employer screening or a hiring
  probability estimate.
- Matching remains deterministic and evidence-linked; imported claims remain
  pending until the candidate confirms them.
- Packets require assurance and approval. External effects require separate
  approval plus the live runtime switch.
- Local receipts are not proof that an employer received anything.
- Connected-account sending, a hosted backend, signed desktop packaging,
  notarization, and automatic updates remain outside this release.
