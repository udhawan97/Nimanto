# Nimanto v0.4.0 — Inspectable History

Nimanto v0.4.0 adds bounded, candidate-visible history and current-view counts
without weakening the evidence, assurance, approval, or local-first boundaries.
It remains a source-distributed local beta: there is no hosted candidate backend,
signed desktop application, connected-account sender, employer screening, legal
advice, hiring prediction, or application submission.

## What changed

### 1. Stored history and export v2

The new **Stored history** section reads cursor-paginated profile versions and
match runs only when opened. The workbench disables its export download control
until the candidate acknowledges a sensitive-data warning; the authenticated
local API remains directly callable. `nimanto-local-beta-v2` /
`nimanto_export_v2` adds retained profile, match, and assurance datasets while
excluding sessions, invitation secrets, deletion internals, and generated packet
files. The JSON is an inspection export, not a restore archive, immutable role
history, online backup, or replay proof.

### 2. Packet history and assurance comparison

Candidates can generate another unapproved packet for an application and inspect
stored generations newest-first. Comparisons cover literal changed canonical
fields, claim count, authorization wording, generation time, profile version,
canonical hash, and artifact-manifest changes. They are called history—not
lineage—because no predecessor relationship is stored. Status and manifests are
labeled current mutable fields. Assurance runs
use packet-local ordinals; the database-wide ordering sequence is never returned.

### 3. Record-review queue

Applications now include a derived record-review queue. A non-withdrawn record
enters after 336 elapsed hours from the newer of application creation and the
latest candidate-recorded outcome. The due-ordered view shows that exact
baseline and computed due time. No reminder or new status is stored, and silence
never becomes a rejection or other inferred employer outcome.

### 4. Literal profile and match comparison

Profile diffs show exact added and removed claim IDs plus exact authorization
wording. Neutral A/B labels remain true for same or reverse-ordered selections.
Candidate-selected same-role match runs disclose stored run/profile IDs,
timestamps, rule versions, bands, blockers, reference hashes, and result hashes.
Current job fields are explicitly a mutable snapshot. A changed result is not
attributed to any cause, and the stored input hash is identified as a reference
hash rather than a content hash.

### 5. Application cohort counts

Applications can be counted inside an explicit creation-date window using the
browser's named time zone. Optional filters use current role source and current
match classification. It contains the five domain match bands plus two
mutually exclusive state buckets: unmatched means no stored match, while unknown
preserves an unrecognized stored band. The view shows raw sample/outcome counts
only—no rates, predictions, or reconstructed historical values.

## Correctness and privacy

- History cursors resolve through a record owned by the same tenant and scope;
  foreign cursors fail closed.
- Latest match and packet selection use timestamp plus ID tie-breaking.
- The dashboard loads latest working records; retained histories stay on-demand.
- Export v2 includes all retained history datasets but never exposes the global
  assurance sequence.
- Existing candidate confirmation, packet assurance, packet approval, exact
  action approval, and reset-on-restart runtime gates are unchanged.

## Upgrade

Pull or download the v0.4.0 source, then install the locked dependency graph:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Existing local workspaces are upgraded in place when the API opens their PGlite
database. Back up `.nimanto-data/` while the API is stopped before moving a
workspace between releases. No schema downgrade is claimed.

## Verification

The release gate covers:

```bash
pnpm check
pnpm build
pnpm test:e2e
pnpm audit --prod --audit-level high
pnpm licenses:check
pnpm sbom:release
pnpm sbom:check
graphify update .
```

The suite runs nine sequential Desktop Safari/WebKit journeys, including the
public-site reflow and metadata matrix, literal stored-history comparison,
packet and assurance history, application cohort counts, the record-review
empty state, sensitive export confirmation, approval gates, deletion recovery,
long-hash containment, and 320 px layout checks. Unit tests own the exact
336-hour boundary, due-time math, and minute-level ordering.

## Unchanged boundaries

- Imported claims remain pending until the candidate confirms them.
- Packets still assemble from confirmed evidence and locked authorization
  wording only.
- Gmail, Outlook, form submission, desktop packaging/signing/notarization,
  hosted identity, backup guarantees, and production legal review remain outside
  this release.
- The interface remains dark only; no light palette is claimed.
